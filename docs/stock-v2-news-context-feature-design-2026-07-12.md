# 股票 V2 消息脉络功能设计

>
> 状态：按本文设计实现并持续验证
>
> 关联说明：[股票 V2 工作台关键点](./stock-agent-workbench-v2-key-points-2026-06-18.md)、[股票 V2 主题机会发现技术设计](./stock-v2-opportunity-discovery-technical-design-2026-06-26.md)、[股票 V2 组合哨兵能力设计](./stock-v2-portfolio-sentinel-design-2026-07-02.md)

## 1. 功能名称与定位

功能正式名称为 **消息脉络**。

页面说明使用：

> 从新闻中归纳市场主题，追踪主题演进与板块轮换。

消息脉络属于股票 V2 的消息面能力，不新增股票 V2 一级导航。推荐入口为：

```text
股票 -> 监控与消息 -> 消息面 -> 消息脉络
```

消息脉络不是新闻摘要页，也不是把相似新闻简单拼接。它是股票 V2 的长期信息压缩与主题演进能力，负责把大量短期新闻转化成更精炼、可持续更新、可追溯、可复核、可检索的市场主题。

## 2. 背景问题

当前消息面会持续产生原始消息、标准消息、股票关联、检索资料和归纳记录。普通快讯具有以下特点：

- 数量增长快，重复报道多。
- 单条消息价值衰减快，但其反映的主题可能持续数周或数月。
- 长期保存全部正文和检索资料会持续增加存储与检索成本。
- 直接按时间删除又可能丢失尚未归纳、尚未复核或仍被其他功能依赖的证据。
- 零散新闻能提示市场叙事，却很难直接回答主题处于什么阶段、当前主线是否退潮、下一批资金可能流向哪里。

因此需要在消息采集与后续决策之间增加一层长期信息资产：消息脉络。

## 3. 核心目标

本功能有两个必须同时完成的核心目标。

### 3.1 归纳压缩新闻资产

- 按小时、四小时和每日逐级归纳新闻。
- 合并重复报道，保留冲突和不同影响方向。
- 每日归纳成功后，安全删除已被主题和精简证据替代的普通新闻正文、临时摘要、旧关联和旧检索资料。
- 任一环节失败时不删除原新闻，并允许从失败阶段继续处理。
- 压缩结果必须真实降低当前存量和磁盘占用，不能只是新增摘要而保留全部旧资产。

### 3.2 发现并持续完善可用主题

- 从新闻中发现潜在市场主题，而不仅是已知股票的相关新闻。
- 通过后续多次归纳和复核持续补充事实、反面证据、阶段变化和影响对象。
- 主题必须能够服务当前主线识别、退潮判断、接力方向发现和板块轮换研究。
- 主题只能产生观察方向和机会线索，后续仍进入现有机会研究、策略生成、操作复核、安全检查和人工确认流程。

## 4. 明确非目标

- 不设小时事项数、主题数、每日更新数或压缩比例目标。
- 不为了减少数量而强行合并不同主题。
- 不用相似程度自动认定事实、决定主题归并、建立因果关系或删除原新闻。
- 不建设通用复杂知识图谱，也不引入新的图存储。
- 不新增另一套泛化复核体系，优先复用现有组合哨兵和操作复核。
- 不自动买卖，不直接修改持仓，不绕过现有人工确认和安全检查。
- 不替代单条重大新闻的即时提醒。
- 不长期保存全部小时摘要、四小时摘要及其独立向量索引。
- 不把短期主题直接写入股票长期画像。
- 不新增股票 V2 一级入口。

## 5. 核心概念

### 5.1 原始消息

从消息源抓取的短期暂存内容，用于去重、归一化和故障追溯。它不是长期资产。

### 5.2 标准消息

经过格式统一、时间处理、去重和质量标记后的新闻。三级归纳以标准消息为主要输入。

### 5.3 主题

一个长期存在、可以持续演进的市场事项。例如某项政策的推进、某条产业链供需变化、某类技术突破及其市场影响。

主题不是一条新闻，也不是一天的摘要。它具有稳定身份，可以经历多次更新、阶段切换、沉寂和再启动。

### 5.4 主题版本

主题每次发生实质变化后保存的不可变记录。主题版本必须说明本次新增了什么、削弱了什么、仍有哪些冲突和未决问题。

历史复核始终展示当时使用的主题版本，不能因当前主题继续变化而改写旧结论。

### 5.5 精简证据

原新闻删除后仍长期保留的最小追溯信息，包括：

- 来源。
- 标题。
- 发生时间。
- 去除敏感参数后的来源链接。
- 内容指纹。
- 归属主题和主题版本。
- 证据作用：支持、削弱、反驳或仅作背景。
- 经裁剪的必要摘要。

精简证据不保存完整正文、完整外部页面或敏感查询参数。

### 5.6 实质变化

实质变化指足以改变主题理解、阶段、影响对象、可信程度、催化条件或失效条件的变化。重复转载、同义改写和没有新增信息的消息不属于实质变化。

## 6. 总体流程

```text
消息采集与标准化
-> 每小时写入确定性连续性检查点
-> 每四小时完整消费新闻并更新主题
-> 每日增量物化发生变化的主题结论并执行一次影响复核
-> 主题当前状态和历史阶段建立向量索引
-> 主题进入 MCP 供 CLI 检索
-> 满足全部安全条件的原新闻进入清理
-> 主题继续被后续归纳、组合哨兵、机会研究和策略生成使用
```

重大政策、财报、监管变化和直接影响当前持仓的突发消息仍纳入后续四小时归纳；即时影响复核属于独立实时能力，不由历史补处理或本三级调度重复实现。

## 7. 三级归纳机制

### 7.1 每小时确定性检查点

每小时检查点负责：

- 持久化小时窗口连续性和调度进度。
- 不认领原始新闻，不调用模型，不创建主题版本。
- 让四小时父窗口可以精确判断其四个小时子窗口是否完整。

小时检查点与新闻数量无关；空窗口和有新闻窗口使用同一条确定性路径。

### 7.2 每四小时归纳

每四小时归纳负责：

- 在四个小时检查点完整后，认领并完整消费本周期尚未形成终态的原始新闻。
- 检查迟到消息、失败批次和历史任务追加清单。
- 把新增证据与主题当前结论比较，判断是否发生实质变化。
- 核实高影响、来源冲突、单一来源和证据不足的事项。
- 更新主题阶段、影响对象、正反证据、催化条件和失效条件。
- 发现主题之间的上下游、替代、竞争、资金外溢和轮换承接关系。
- 有实质变化时触发一次主题驱动的组合影响复核。

四小时是唯一的常规模型归纳层。若任何小时检查点缺失，四小时归纳必须等待或明确失败；若新闻未得到覆盖、噪音或受保护延后的终态，不能推进删除资格。

### 7.3 日级增量物化

日级处理负责：

- 从当天四小时输出中按稳定主题身份去重，只取每个发生变化主题的最新版本。
- 确定性复制为显式每日版本，不再把全部当前主题交给模型复核。
- 没有变化的主题不生成重复每日版本。
- 当存在增量主题时执行一次完整影响复核。
- 为满足安全条件的新闻生成清理计划。

日级物化成功不等于立刻无条件删除。只有通过第 15 节全部安全门的新闻才能进入实际清理。

### 7.4 迟到消息与补跑

- 迟到消息按照实际发生时间补入对应主题，但由后续运行完成归纳。
- 服务停止后恢复，应从上次成功覆盖位置继续处理。
- 同一时间窗口重复执行不能重复创建主题、重复生成主题版本、重复触发复核或重复删除。
- 分批处理只用于保障稳定运行，不构成功能数量限制。
- 只有全部分批成功后才能推进本周期的覆盖位置和删除资格。

## 8. 不限制归纳数量

本功能不设置任何业务数量上限：

- 不限制一小时可以产生多少事项。
- 不限制四小时可以更新多少主题。
- 不限制一天可以形成多少主题变化。
- 不限制一个主题可以包含多少有效证据。
- 不限制一条新闻可以支持多少相关主题。

系统可以为稳定运行采用分页和小批量处理，但必须最终完整消费全部输入。

归纳质量优先于压缩数量：

- 同一事件、同一因果链和同一时间进展可以归并。
- 影响方向、因果关系或时间阶段不同的内容必须分开。
- 不确定是否应该合并时，应保留为独立事项或等待后续归纳。
- 宁可暂时多保留一个主题，也不能错并后删除原始证据。
- 无新闻、无新主题或无实质变化都是合法结果，仍需保留完成记录。

## 9. 主题内容与演进

每个有效主题至少包含以下内容：

- 主题名称和核心逻辑。
- 当前阶段和最近实质变化。
- 已确认事实。
- 推断和影响假设。
- 反面证据、冲突和未决问题。
- 相关行业、股票和基金。
- 龙头、跟随者、滞涨者和潜在接力者。
- 上下游、替代、竞争和资金外溢关系。
- 催化条件和失效条件。
- 可信程度和数据新鲜度。
- 首次出现时间、最近变化时间和历次阶段切换。
- 来源证据及每条证据的作用。
- 最近被哪些复核、机会研究或策略生成任务使用。

### 9.1 主题阶段

主题可以处于以下阶段：

- 萌芽：出现初始线索，证据和市场参与仍有限。
- 扩散：更多来源和相关标的开始响应。
- 加速：信息、价格表现和市场参与同步加强。
- 过热：拥挤度上升，预期可能提前透支。
- 分歧：支持和反面证据同时增加，龙头与跟随者表现分化。
- 退潮：市场参与和相对强度持续下降。
- 沉寂：短期缺乏新增催化和市场响应。
- 再启动：旧主题在新证据和市场确认下重新活跃。

阶段由消息和市场数据共同判断，不能只因新闻数量增加就认定主题加强。

### 9.2 主题合并、拆分、更名和重启

- 系统可以提出主题合并或拆分建议，但必须保留原主题和历史版本的继承关系。
- 合并和拆分不能改写历史复核、提醒、机会和策略所使用的旧版本。
- 主题更名只改变当前展示名称，不改变历史身份和证据关系。
- 沉寂主题重新出现时，应先判断是旧主题再启动还是新的独立主题，并记录判断理由。
- 错误归并必须可以恢复，在恢复完成前相关原新闻不得删除。

## 10. 主题如何服务板块轮换

新闻只能发现叙事变化，不能单独确认资金已经轮换。主题判断必须结合：

- 板块相对强弱。
- 上涨股票的覆盖范围。
- 龙头、跟随者和滞涨者的表现差异。
- 成交活跃程度和量价变化。
- 原主线开始分歧时，其他方向是否提前走强。
- 海外市场、商品价格和国内板块之间的先后关系。
- 未来几天是否存在明确催化。
- 当前数据是否新鲜、完整和相互一致。

轮换线索稳定输出：

- 当前主线。
- 正在加速的主题。
- 正在退潮的主题。
- 潜在接力板块。
- 接力板块中的龙头、跟随和滞涨候选。
- 支持轮换的确认信号。
- 推翻轮换判断的证伪信号。
- 当前结论属于仅有消息线索、等待行情确认，还是已经得到多类数据支持。

轮换线索只能进入观察和机会研究，不能直接生成交易操作。

## 11. CLI 公开资料核实

归纳任务应强鼓励 CLI 主动搜索公开资料，而不是只依赖项目内已有消息。

以下情况必须搜索核实：

- 可能对持仓或活跃策略产生重大影响。
- 不同来源互相冲突。
- 重要结论只有单一来源。
- 证据不足以判断主题阶段或影响方向。
- 需要确认产业链关系、政策原文、公告或财报事实。

核实过程必须保留：

- 搜索过什么问题。
- 查看过哪些公开来源。
- 哪些结论得到支持、削弱或反驳。
- 哪些问题仍无法确认。
- 搜索不可用或失败的原因。

搜索失败不能伪装成已核实。对应主题应降低可信程度并保留不确定性，相关原新闻不得进入删除阶段。

## 12. 复核闭环

### 12.1 触发规则

- 每小时：普通变化只归纳，重大突发消息可以立即复核。
- 每四小时：只有存在实质变化时触发一次影响复核。
- 每日：固定触发一次完整影响复核。
- 同一主题的同一版本不能因即时提醒、四小时归纳和日级物化而重复产生相同提醒或相同操作复核。
- 新版本发生新的实质变化时，允许再次复核。

### 12.2 复核范围

复核必须检查：

- 最近变化主题对当前持仓的影响。
- 最近变化主题对活跃策略及其失效条件的影响。
- 是否需要生成提醒或进入单票操作复核。
- 是否出现值得进入主题机会研究的新方向。
- 当前主题之间是否出现新的轮换承接关系。

周期复核必须直接获得本周期全部变化主题的明确清单，不能只靠相似度检索决定“最近发生了什么”。当变化主题超过单次处理容量时，应分页完整消费，并在一个逻辑复核中汇总结论。只有全部页面成功处理后才能推进复核水位。

### 12.3 复用现有能力

主题驱动的组合影响复核复用现有组合哨兵：

```text
最近变化主题
-> 组合哨兵判断组合影响
-> 无影响则保存结论
-> 有风险则生成提醒
-> 需要具体处理时按单只股票进入现有操作复核
-> 继续执行安全检查和人工确认
```

非持仓方向的潜在主题不创建空操作复核，而是形成机会线索，进入现有主题机会研究。

### 12.4 提示词要求

归纳和复核提示词必须固定包含以下不可覆盖的要求：

- 检查最近变化过的全部主题。
- 区分事实、推断、反面证据和未决问题。
- 对重大、冲突或证据不足的内容主动核实公开资料。
- 记录本次实际检查过的主题和主题版本。
- 不能把相似程度当成事实或因果关系。
- 不能直接修改持仓、策略或交易记录。
- 数据不足时必须降低可信程度，不得强行给出操作建议。

用户自定义的附加提示只能补充关注重点，不能覆盖上述完整性和安全要求。

## 13. 主题向量索引

所有有效主题都必须建立可用的向量索引，不只处理少数重点主题。

### 13.1 索引范围

长期保留两类主题索引：

- 当前主题索引：反映主题现在的完整状态。
- 历史阶段索引：保留每日结论和重要阶段切换，用于研究过去的主题演化和轮换周期。

小时摘要和四小时临时摘要不长期单独建立索引，避免压缩后再次产生大量新资产。

### 13.2 索引内容

主题索引至少包含：

- 主题名称和核心逻辑。
- 当前阶段和最近实质变化。
- 相关行业、股票和基金。
- 龙头、跟随、滞涨和潜在接力关系。
- 上下游、替代、竞争和资金外溢关系。
- 催化条件、风险和失效条件。
- 支持证据、反面证据和未决问题。
- 可信程度和更新时间。

### 13.3 更新与失败处理

- 主题发生实质变化后更新当前主题索引。
- 新索引成功前继续保留上一版可用索引，避免检索空窗。
- 新索引成功后再把旧当前索引标记为历史或清理。
- 向量模型切换、索引规格变化或索引过期时，应提供完整重建能力。
- 索引失败时，前端显示失败原因、最后成功时间和重试入口。
- 索引不可用时，MCP 不得返回伪装成语义结果的关键词结果。
- 索引不可用时，对应原新闻不得删除。

## 14. MCP 与 CLI 检索

消息脉络复用股票模块现有 MCP，不新增独立服务。

MCP 至少提供两项只读能力：

- 按语义检索消息脉络。
- 读取主题完整详情。

### 14.1 语义检索结果

检索结果至少返回：

- 主题稳定身份和当前版本。
- 主题名称和当前阶段。
- 核心逻辑和最近实质变化。
- 与检索问题的相关程度。
- 相关板块、股票和基金。
- 支持证据和反面证据摘要。
- 催化因素和失效条件。
- 最近复核时间。
- 内容新鲜度和索引状态。

相似结果只代表值得进一步查看的候选，不能代表事实关联、因果关系或交易结论。

### 14.2 主题详情

CLI 从检索结果继续读取：

- 当前完整主题内容。
- 历史版本和阶段切换。
- 精简来源证据。
- 相关主题及关系依据。
- 相关提醒、复核、机会和策略摘要。

MCP 只提供受控查询，不允许 CLI 通过 MCP 删除新闻、改写主题、修改持仓或直接产生交易记录。

### 14.3 周期复核与语义检索的分工

周期复核由系统直接提供最近变化主题的轻量清单，确保完整覆盖。CLI 再通过 MCP 读取这些主题的详情，并使用语义检索发现相邻主题和隐藏关系。

因此：

- 最近变化清单负责“不漏项”。
- 语义检索负责“发现关联”。
- 两者不能互相替代。

## 15. 新闻删除安全门

每日归纳后，一条新闻只有同时满足以下条件才能进入清理：

- 已归入一个或多个主题，或明确判定为重复、噪音。
- 对应主题和主题版本已保存成功。
- 精简证据已保存成功。
- 当前主题向量索引已经可用。
- CLI 能通过 MCP 检索并读取对应主题。
- 主题影响复核已经完成，或明确记录无需复核。
- 不存在尚未解决的来源冲突和重要未决问题。
- 不存在仍需原文的归纳任务、组合哨兵、消息监控、提醒、操作复核、机会研究或策略生成任务。
- 已经过可恢复的待清理阶段。

以下内容可以延长正文保留：

- 官方公告和财报原文。
- 政策和监管原文。
- 存在冲突的重要证据。
- 正在被运行中任务引用的材料。
- 主题错误归并或拆分尚未恢复的材料。

前端必须显示受保护原因、预计保留时间和解除条件。

### 15.1 实际清理范围

清理应同步处理：

- 普通新闻正文和不再需要的详细内容。
- 重复快讯。
- 已完成使命的小时和四小时临时摘要。
- 新闻产生的旧股票关联候选。
- 新闻对应的旧向量资料。
- 无效缓存和孤立记录。

长期保留：

- 当前主题。
- 每日主题结论和重要阶段版本。
- 精简证据。
- 防止重复采集所需的内容指纹。
- 历史复核、提醒、机会和策略当时使用的主题版本快照。

### 15.2 清理完整性

新闻、关联、索引和运行状态属于不同资产，不能假设一次操作全部成功。清理必须分阶段、小批量、可重试：

- 任一步失败都不能把新闻标记为完全清理。
- 服务重启后可以从未完成阶段继续。
- 已完成阶段重复执行不会重复删除或破坏计数。
- 只有所有关联资产清理完成后才推进清理水位。
- 清理失败必须在页面可见，不能只写后台日志。

## 16. 知识拓扑

第一阶段不建设复杂知识图谱。知识拓扑从主题已有信息和关系中派生，围绕：

```text
主题
-> 行业链位置
-> 受益与受损方向
-> 股票和基金
-> 当前阶段
-> 上下游、替代、竞争主题
-> 资金外溢和轮换承接关系
-> 相关机会、策略和持仓
```

只有具备明确证据的关系才能显示为实质关系。单纯语义相似只能显示为“可能相关”，不能表达成支持、反驳或因果。

当多个主题出现共同实体、上下游传导、替代关系或资金此消彼长时，可以形成潜在轮换线索，再进入现有主题机会研究进行公开资料搜索、标的筛选和风险检查。

## 17. 前端可观测性

消息脉络前端按桌面工作台优先设计，保持浅色中性、细边框、低噪音和稳定分栏。它是信息密集的决策工作台，不使用营销页结构、彩色仪表盘、装饰型大卡片或复杂动效。

### 17.1 页面结构

推荐布局：

- 左侧上下文列：主题筛选和主题列表。
- 中央主工作区：主题当前结论、最新变化和版本时间线。
- 右侧检查栏：主题阶段、索引、复核、引用和清理状态。

页面包含四个视图：

- 主题总览。
- 轮换线索。
- 归纳记录。
- 清理记录。

现有原始消息、标准消息和股票关联候选继续保留为近期资产与维护视图，不提升为新的一级导航。

### 17.2 主题列表

主题列表至少展示：

- 主题名称和核心逻辑摘要。
- 当前阶段。
- 最近实质变化。
- 受影响板块和主要股票。
- 支持或削弱主题的证据摘要。
- 可信程度和更新时间。
- 复核状态。
- 向量索引状态。
- 最近被哪些能力使用。

支持按阶段、影响对象、更新时间、可信程度、复核状态和索引状态筛选。

### 17.3 主题详情

主题详情至少展示：

- 当前完整结论。
- 已确认事实、推断、反面证据和未决问题。
- 主题版本时间线。
- 每次阶段切换及其原因。
- 龙头、跟随、滞涨和潜在接力对象。
- 主题关系和轮换线索。
- 来源证据及原新闻是否已清理；状态必须由原新闻真实压缩记录返回，关联新闻不存在时显示未知，不能把缺失字段当成仍保留。
- 相关提醒、复核、机会和策略。
- 当前索引状态、最后成功时间和失败原因。
- 清理覆盖情况和受保护证据。

低频详细信息放入抽屉或折叠区，当前阶段、最新变化、风险、索引异常和复核状态保持可见。

主题关系的数值字段统一表示关系强度，前后端不得把它误读成主题自身的可信程度。

### 17.4 归纳记录

每次归纳运行展示：

- 处理时间范围和覆盖状态。
- 当前进度。
- 已处理消息数量。
- 新建、更新、保持不变、冲突和等待处理的主题数量。
- 公开资料核实情况。
- 产生实质变化的主题。
- 删除、保留和等待清理的新闻数量。
- 失败原因、已用自动重试次数、下次自动重试时间和手动重试入口。

失败记录不能被后续高频小时检查点挤出默认视图。页面固定展示最近一次四小时或日级失败；自动重试耗尽或错误不可重试时明确标为最终失败，并继续保留详情和手动重试入口。

数量是实际结果统计，不构成功能限制。

### 17.5 清理记录

清理页面展示：

- 当前新闻存量和历史处理总量，两者不能混为一谈。
- 已压缩正文数量和实际释放空间。
- 等待清理数量。
- 因索引、复核、冲突或运行引用而保留的数量。
- 最近清理运行、失败阶段和重试状态。
- 受保护证据及保护原因。

### 17.6 完整交互状态

页面必须提供可辨认的加载、空状态、失败、部分完成、索引过期、复核等待、清理失败和不可用状态。筛选、当前主题和打开的详情应尽量反映到可恢复页面状态中。主要操作支持键盘访问，焦点状态清晰。

当前阶段按桌面端和常规笔记本宽度验收，不让移动端适配阻塞本功能。

## 18. 对现有功能的影响

| 现有功能 | 影响与调整 |
| --- | --- |
| 消息源采集 | 采集与标准化主链保持不变，标准消息进入三级归纳。现有按时间直接清理必须先确认消息已经安全覆盖。 |
| 消息面数据资产 | 增加归纳、复核、索引、清理和主题归属状态；区分当前存量与历史处理总量。 |
| 手动清理 | 不能绕过删除安全门，只能清理已经满足条件的安全集合。 |
| 消息搜索 | 近期历史继续搜索原新闻；长期历史优先搜索主题、每日结论和精简证据。 |
| 消息关联候选 | 继续作为消息脉络、组合哨兵和机会研究的召回资产，不再启动独立的逐条消息监控。 |
| 组合哨兵 | 读取自上次成功复核以来发生变化的主题，判断持仓影响；不能在原新闻删除后失去上下文。 |
| 提醒与操作复核 | 保存当时使用的主题版本快照；同一版本避免重复提醒，新版本发生实质变化可以再次复核。 |
| 主题机会发现 | 增加从消息主题进入现有机会研究的入口；消息主题与用户发起的研究机会保持独立，不混成同一对象。 |
| 策略生成 | 增加主题阶段、正反证据、催化和失效条件；明确区分近期新闻和长期主题。 |
| 股票画像 | 短期主题保持独立，只作为动态上下文，不直接污染长期画像。 |
| 向量检索 | 长期检索重心从旧新闻转向主题当前状态和历史阶段；删除新闻时同步清理旧索引。 |
| 执行留痕与复盘 | 记录归纳、公开搜索、主题版本、复核和清理摘要，但不把即将删除的新闻全文复制到长期记录。 |
| 股票总览 | 增加今日新增主题、发生实质变化、待复核、待清理和索引异常摘要。 |

以下能力原有职责不变，只作为消息脉络的上下文或下游消费者：

- 行情、日线和分钟走势。
- 组合、持仓和人工交易记录。
- 操作安全检查。
- 用户确认、拒绝和延后处理。

## 19. 历史数据与兼容性

- 现有历史标准消息采用分批补归纳，不在功能上线时一次性全部删除。
- 历史消息先进入只归纳、不删除的观察阶段，验证主题质量和检索效果后再开放自动清理。
- 现有提醒、操作复核、机会、策略和执行记录继续可读。
- 原新闻清理前，依赖方必须已经保存必要的主题版本或精简证据快照。
- 主题合并、拆分和更名不修改旧记录中的历史主题版本。
- 已清理消息的内容指纹继续参与防重复判断，避免消息源重放后重新产生同一新闻。
- 当前按时间清理原始消息的路径需要先修正：不得只处理有限批次后删除截止时间前的全部消息。

## 20. 日志、审计与信息边界

服务日志只记录：

- 归纳任务启动失败、异常退出和恢复失败。
- CLI 或 MCP 不可用。
- 向量索引失败。
- 主题、证据或复核保存失败。
- 清理失败、重试失败和孤立资产修复失败。

服务日志不记录：

- 完整新闻正文。
- 完整提示词和完整 CLI 输出。
- 每条成功归纳或每次成功 MCP 查询。
- 带敏感参数的来源链接。
- 访问凭据、会话信息或密钥。

用户可见的归纳、复核、索引和清理过程写入对应运行记录，通过页面恢复查看。关键删除和人工重试进入审计记录。外部来源链接保存前必须移除查询参数和片段，外部错误和 CLI 输出必须裁剪并脱敏。

## 21. 验收标准

### 21.1 新闻压缩

- 每小时、每四小时和每日归纳可以持续运行、补跑和幂等重试。
- 不限制事项、主题和主题更新数量。
- 积压、迟到消息和跨页处理不会漏消息。
- 每日成功后能删除满足条件的普通新闻正文、临时摘要、旧关联和旧索引。
- 压缩前后当前存量、磁盘占用和实际释放空间可观察。
- 任一安全门失败时原新闻不删除。
- 清理中断后可继续，最终不存在孤立索引、孤立关联或错误计数。

### 21.2 主题可用性

- 每个有效主题都能在前端查看。
- 每个主题都有当前结论、历史变化、正反证据、阶段、影响对象、催化和失效条件。
- 主题能够形成当前主线、加速、退潮和潜在接力方向。
- 数据不足时明确标记为仅有消息线索或等待行情确认。
- 主题合并、拆分、更名和再启动保留完整历史。

### 21.3 向量与 MCP

- 所有有效主题当前状态都有可用向量索引。
- 每日结论和重要阶段切换具有历史向量索引。
- 前端可以看到每个主题的索引状态、更新时间、失败原因和重试入口。
- CLI 可以通过 MCP 语义检索主题并读取完整详情。
- 无可用索引时明确失败，不返回假语义结果。
- 原新闻删除后，CLI 仍能检索主题并追溯精简证据。

### 21.4 复核与现有闭环

- 每四小时的实质变化和每日完整归纳按规则触发复核。
- 复核完整消费本周期全部变化主题，并记录实际使用的主题版本。
- 同一主题同一版本不会重复提醒，新版本可以重新触发。
- 组合影响继续进入组合哨兵、提醒、单票操作复核、安全检查和人工确认。
- 非持仓主题只形成机会线索，继续进入现有主题机会研究。
- 历史提醒、复核和机会在原新闻删除后仍可追溯。

## 22. 推荐交付顺序

### 第一阶段：安全基线

- 统计消息、关联、向量和磁盘占用。
- 修正现有按时间直接清理可能漏处理消息的问题。
- 建立归纳覆盖位置、补跑和幂等规则。

### 第二阶段：只归纳不删除

- 上线主题、主题版本和精简证据。
- 跑通每小时、每四小时和每日归纳。
- 上线主题总览、主题详情和归纳记录。
- 使用真实历史数据观察错误归并、漏归纳和主题可用性。

### 第三阶段：向量、MCP 与复核

- 为主题当前状态、每日结论和重要阶段建立向量索引。
- 把主题语义检索和详情查询加入现有 MCP。
- 让组合哨兵、主题机会研究和策略生成消费主题。
- 上线轮换线索和索引可观测状态。

### 第四阶段：自动清理

- 先提供清理预览和手动安全清理。
- 验证原新闻删除后前端、CLI、历史复核和机会证据仍完整。
- 再开启每日自动清理和失败恢复。

## 23. 最小实现判断

消息脉络确有必要，因为现有能力可以采集和检索新闻，但缺少长期压缩、主题演进和轮换发现闭环。

最小正确实现是：

```text
主题 + 主题版本 + 精简证据
-> 小时检查点 + 四小时模型归纳 + 日级增量物化
-> 现有向量与 MCP
-> 现有组合哨兵和机会研究
-> 安全清理
```

第一阶段不需要新的向量库、新的 MCP 服务、新的图存储、通用提示词框架或新的泛化复核体系。只有现有能力在真实数据规模下明确无法满足时，才考虑扩大技术方案。

## 24. 配置与历史补处理实施约束

本节是对前述设计的实现收口，优先级高于早期关于固定新闻批量的描述。消息脉络不再提供“每批新闻数”，也不使用新闻条数决定一次归纳的边界。

### 24.1 配置页面

消息脉络页面提供独立配置抽屉，可修改：

- 自动归纳总开关。开启时四小时模型归纳必须启用。
- 小时检查点、四小时模型归纳和日级增量物化开关；小时和日级可按需要关闭。
- 自动安全清理开关。默认关闭，历史追平和全部安全验证通过前不得清理。
- 清理等待期，只提供 1、3、7、14、30 天。
- 附加研究要求，最多 2000 字，只能增加关注重点，不能覆盖固定完整性和安全规则。

页面只读展示：

- 固定的 1 小时、4 小时、24 小时层级。
- 根据整理后文字量自动分片，且不限制每日新闻、主题、轮换线索和主题变化总量。
- 上次和下次归纳、上次清理、最近错误。
- 消息归纳、影响复核、向量和命令行检索条件。
- 历史待处理数量、时间范围和预计自动分片工作量。

旧“每批新闻数”字段通过一次性结构迁移删除；运行时不保留旧字段分支。单次输入文字量保护是固定的内部安全措施，不作为业务配置。

### 24.2 不限量自动分片

- 四小时窗口先形成完整、持久化的新闻处理清单，再按整理后的实际文字量选择本次输入。
- 一次模型处理完成后，每条输入必须具有已覆盖、重复噪音或受保护延后的明确结果。
- “已覆盖”不能只靠模型声明：每条非噪音、非重复、非延后的新闻必须且只能进入本分片一个有效主题变化，并保存对应精简证据；错误主题、跨分片证据、重复证据和没有证据的覆盖结果均拒绝落库。仓储层在写入时再次执行同样的防御校验。
- 一个分片产生的主题版本立即保存并建立向量索引；索引失败时不得开始下一分片。
- 输入仍然过大时继续分片，直至清单内全部新闻和主题得到明确结果。
- 四小时窗口直接消费原始新闻，并通过时间点受限的主题语义检索匹配稳定主题；不再消费小时模型输出。
- 日级处理只把四小时输出中每个发生变化主题的最新版本确定性物化为每日版本，不再执行首轮加全主题收敛的两段模型任务。
- 日级和最终当前结论使用稳定版本身份保证重试幂等；服务在版本写入后、运行清单更新前中断时，重启只重建清单，不重复创建版本。
- 每个实时四小时或日级窗口的整次尝试最多运行 30 分钟；影响复核的单次模型执行最多运行 10 分钟。超时、服务重启中断、上游限流或 5xx、模型未提交以及结果完整性校验失败属于可重试错误，分别在 1 分钟和 2 分钟后自动重试。窗口尝试与后续影响复核各有最多两次重试；额度耗尽和余额不足不自动重试。
- 自动重试复用原窗口和未完成清单，不新建重复窗口。重试耗尽后窗口停留在原自然边界，阻止父层把缺失结果当成完整覆盖，并在归纳记录中持续展示最终失败。
- 只有总量、已覆盖量、剩余量和遗漏量满足完整覆盖条件，归纳运行才能完成。

### 24.3 持久化历史任务

历史补处理由 Owner 在页面确认后启动，并固定最近一个完整小时作为截止点：

- 启动时把截止点以前所有待处理新闻身份写入父任务清单；该清单是暂停、继续、失败重试和服务重启恢复的共同依据。
- 截止点以前只由历史任务处理，截止点以后继续由实时任务处理，二者不得重复认领。
- 历史任务按发生时间从旧到新补齐小时检查点、四小时模型归纳和日级增量物化，包括无新闻但用于证明窗口连续性的完成记录。截止点如果落在四小时或自然日中部，仍形成对应尾部四小时和尾部每日结果。
- 每次只运行一个按文字量形成的分片；分片保存和索引完成后立即释放归纳执行位。
- 历史四小时归纳不执行常规公开搜索或浏览，只允许按窗口截止时间调用主题语义检索和详情读取以确认稳定主题身份；无法安全归类的事项明确延后并保护原文。实时四小时归纳仍按影响和证据规则执行公开核实。
- 调度顺序固定为日级实时物化、四小时实时归纳、小时实时检查点、历史补处理、清理检查。实时任务最多等待当前一个历史模型分片。
- 启动历史任务时，早于截止点的陈旧实时游标一次性快进到截止点之后；启用完整层级时从第一个完整父窗口继续，只启用四小时或每日时则由首个跨越截止点的部分实时窗口接住截止点以后的新闻，且不得认领截止点以前的新闻。
- 暂停在当前分片结束后生效；继续和重试沿用原父任务、原清单、原运行和原进度。主动暂停的任务重启后不自动恢复。
- Owner 的暂停状态与后台执行结果分开保存；已经发出的旧执行结果可以更新覆盖进度，但不能把已暂停任务误改为完成、失败或其他阶段。
- 新分片开始前，父任务“仍在运行”和分片状态在同一持久化事务中确认；Owner 已经暂停时，不得在旧调度快照上继续创建、认领或启动下一分片。
- 服务重启时，执行中的历史分片回到原清单等待继续；正在等待影响复核的归纳保持“等待复核”，原中断复核会关闭并由现有复核调度重新创建，不会把已经完成的归纳误判为失败。
- 最终复核前重新扫描截止点以前的迟到新闻，只向原父任务清单追加新的新闻身份，并从受影响的四小时窗口重建其日级结果。
- 迟到新闻可以早于任务最初记录的起点；每次刷新进度都从冻结清单重新计算最早自然日，保证更早到达的新闻也能进入对应小时窗口。

历史父任务展示固定范围、当前窗口、任务总量、明确覆盖量、剩余量、遗漏量、每一阶段的窗口与输入进度、累计模型调用次数、失败次数、模型耗时、当前阶段、错误和预计工作量。受保护延后属于明确处理结果，不得伪装成遗漏；它仍会通过保护原因阻止不安全清理。

最终阶段还要展示“历史每日输出版本总数、已关联最终复核版本数、未关联版本数”。这三项必须来自后端持久化关系的实际统计；接口读取失败或旧记录尚无统计时，页面显示未知或等待统计，不得用零伪装成完整覆盖。

### 24.4 历史版本、索引与命令行检索

- 主题版本同时记录内容实际生效时间和实际处理时间；历史页面按内容实际生效时间排序和展示。
- 历史版本永远保存结论和精简证据，但较旧内容不得覆盖更晚的当前结论、阶段、合并状态或轮换判断。
- 每个历史四小时模型分片形成的版本在下一模型分片开始前必须可通过向量检索找到。
- 每日版本和实质变化版本长期保留索引；不再需要的小时、四小时临时版本索引在每日结论稳定后清理，版本记录本身保留。
- 历史最终索引按固定的小页逐次补齐，每页后释放向量执行位；已就绪向量就是可恢复进度，服务重启后继续扫描未就绪页，不允许一次全量索引长时间阻塞实时归纳。最终索引范围覆盖固定的最终当前每日归纳结束时点，而不只覆盖历史截止点。
- 命令行语义检索默认返回当前主题；指定历史时间时，返回该时间点以前实际最新的主题版本。小时或四小时临时索引已经清理时，可以用同主题最近保留的每日或实质变化索引负责相似度召回，但最终返回内容和详情必须还原到该时间点的实际最新版本，不得用更旧版本冒充。
- 前端同时展示命令行工具注册状态和最近一次真实语义检索、详情读取的验证结果，明确区分待真实验证、已验证和验证失败。

### 24.5 最终安全门

历史清单全部获得明确结果后，父任务仍需依次完成：

1. 再次扫描截止点以前的迟到和遗漏新闻。
2. 只对本历史父任务影响过的稳定主题，按当前最新版本增量物化一次“当前日结论”；不再次执行全主题模型归纳。
3. 确认全部当前主题、每日版本和重要历史版本的向量内容与当前文本一致。
4. 执行一次完整影响复核，检查持仓、监控、提醒、机会和策略。复核启动时冻结这五类对象的稳定清单；其中“监控”同时包含系统内置监控任务和 Owner 建立的盯盘对象，并使用带类别的稳定身份避免碰撞。模型必须逐类分页读取并返回已检查对象，空类别也要明确返回空清单，后端精确校验漏项、重复项和伪造项。即使组合上下文超过单次提示保护值，任务身份、两类运行身份、必要检索工具、冻结数量、分页规则和精确覆盖契约也不得被裁掉。
5. 真实调用一次命令行主题语义检索，并读取实际命中主题的详情。
6. 确认父任务清单中每条新闻恰好具有一个明确结果，剩余和遗漏均为零。

任一步失败，历史任务不得完成。历史任务未完成、暂停或失败，以及每日归纳、影响复核、向量索引、命令行检索任一安全条件失败时，后端拒绝新闻清理。历史重建过程不产生过期持仓提醒，只在最终当前复核中产生一次有效判断。

自动安全清理开关也受同一安全条件约束：后端只有在历史待处理为零、没有阻塞中的历史任务、向量模型可用且存在已复核每日结论后，才会继续对当前全部已覆盖或噪音新闻执行一次不删除正文的完整预检。预检复用真实清理安全门，并针对每个不受引用保护的当前主题重新执行语义检索和详情读取；无关主题、旧版本或伪造的成功记录不能解锁开关。全部当前候选都有明确安全结果后，才允许从关闭改为开启。前端确认弹窗只负责说明影响，不能替代后端校验。

最终影响复核成功后，父任务还要把该任务每个每日输出主题版本与最终复核运行建立明确、持久化的对应关系，包括随后已合并或已归档、因而不再出现在当前主题清单里的历史主题。该对应关系只证明“这个历史父任务的最终复核覆盖了这个每日输出”，不得批量修改所有旧版本自身的复核状态，也不得让无关复核替代当前父任务。清理退役主题时必须同时核对父任务已完成、最终当前复核已完成、每日输出属于同一父任务且关联仍指向父任务当前记录的最终复核运行。

最终影响复核产生的命中、操作复核、提醒、结果和运行完成状态必须作为一次原子发布：中途任一步失败不得留下可见的部分结果；相同运行重试或重复提交只能得到同一组派生对象，不能重复提醒。

清理候选关联到仍活跃的主题时，必须真实检索当前版本；关联到已合并或已归档主题时，必须以其已复核每日版本的实际生效时间执行历史语义检索并读取同时间点详情。任何一种真实调用失败都记录验证原因并继续保护原新闻。

真正删除单条新闻前，清理任务只在很短的临界区内同时占用归纳和向量维护执行位，并再次检查主题、索引、命令行检索缓存和所有活跃引用；主题在第一次检查后发生变化、执行位被占用或任一复检失败时都保留原文。关联候选、原始新闻和正文压缩在同一个数据事务内完成，失败不得先删关联记录。

一次清理运行采用两段式安全校验：第一段遍历本次截止点以前的全部候选，完成每日复核、向量、真实命令行检索和详情读取等硬性安全门；任一候选存在硬性失败时，在删除任何正文前让整次运行失败。仅因活跃引用、未决研究或冲突而受保护的候选可以保留，不阻塞其他已经完全验证的候选。第一段全部通过后才进入第二段逐条清理，并在每条正文删除前再次执行短临界区复检；复检期间状态变化时保留该条新闻，等待下一次运行。

噪音新闻也不能用任意较晚的每日物化放行。实时噪音必须沿其直接处理的四小时运行进入已复核每日父链；历史噪音必须进入同一历史任务的四小时和每日父链，并由该历史父任务固定记录的最终当前复核运行统一确认。小时记录只证明窗口连续性，不作为新闻终态证据；无关手工运行、窗口不包含该新闻或父链缺口都继续保护原文。

### 24.6 历史数据验收与上线顺序

- 使用 16,001 条新闻验证父清单完整、每条只处理一次且没有遗漏。
- 验证单日超过 50、500、1000 条新闻仍可通过自动分片达到完整覆盖。
- 验证主题数量超过单次输入承载能力时可以分组完成且不丢主题。
- 验证实时任务最多等待一个历史分片。
- 验证暂停、失败和服务重启后从原进度继续。
- 验证补入旧历史不会让当前主题和轮换阶段回退。
- 验证分片索引在下一分片开始前可检索。
- 验证任何遗漏、复核失败、索引失败或命令行检索失败都会阻止清理。
- 生产环境先补处理约 500 条真实新闻进行人工抽查，确认主题归并、证据和检索质量后，再继续全部历史新闻。
